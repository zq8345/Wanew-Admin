# 已删除的能力：删了什么、从哪取回、什么条件下才该取回

**这份文件记的不是代码** —— 代码在 git 里，`git show <SHA>:<路径>` 一条命令就有。
**记的是"当初那个形状为什么不行"**，因为想恢复它的人最可能重犯的正是形状，
而 `git show` 取回来的恰好是那个形状本身。

⚠️ 每条必须有三样：**取回命令** · **删除时的判据** · **恢复前必须先解决什么**。
只写"删了 X"的条目不算数 —— 那和 `git log` 重复。

---

## `rebakeCategory` — 重烘焙一个机型

**删于** 2026-07-28 · **取回**：
```bash
git show 53150bc9:src/publish.ts
```

**它做什么**：给定一个机型 slug，逐个读该机型下每个产品的 `data/products/{id}.json`，
重新渲染它们的详情页（三语），外加该机型列表页与产品总列表页。

**为什么删**：三个调用点全部去掉后它成了孤儿。三个调用点是——

| 位置 | 触发原因 | 判据 |
|---|---|---|
| `PUT /categories`（`categories.json` 的 `display` 变了） | 改机型显示名 | 与改品类显示名对称：**只写 json，页面等 `rebuild.mjs`** |
| `PUT /models`（`model_display` 变了） | 改机型显示名（另一个真源） | 同上 |
| `PUT /categories`（删机型后"刷总列表"） | 机型集合变了 | 🔴 **实测它什么也没做**，见下 |

**判据是"触发原因"，不是"谁调用了它"**：
> 触发原因是**改显示名** → 删，交给 `rebuild.mjs`
> 触发原因是**产品归属变了** → 🔴 不能删，页面上的产品**集合**变了，构建之前官网会显示一个错误的集合
>
> 这两类的正确答案相反，而它们都叫 `rebakeCategory`。
> （归属变走的是 `publishBulk` / `publishProduct`，那两条一个字没动。）

### 🔴 恢复之前必须先解决的：**形状**

逐产品 `readFile` 再渲染这个形状，**在 Workers 免费版 50 子请求上限下对大机型不成立**。
实测（含 `loadCtx` 12 + commit 5）：

```
mini                 36 个产品   62   🔴 超
standard             13          39   ✅
standard-actuated     6          32   ✅
standard-circular     2          28   ✅
performance-gen-1     1          27   ✅
performance-gen-3     5          31   ✅
enterprise            5          31   ✅
```

⚠️ **62 已经是砍掉行尾探测之后的数字**（砍之前 157）。剩下的 62 里 36 次是每个产品的
`{id}.json`，**渲染必需，砍读解决不了**。

⚠️ 而且调用点是循环累加：一次改 2–3 个机型就超（`12 + 22 + 15 + 5 = 54`）。

> **⇒ 恢复它之前先回答："36 个产品的机型怎么在 50 次以内重烘焙完？"**
> 分批多 commit 会丢掉原子性（每个断点后面都是一个已生效的分支）。
> 没有答案就不要恢复 —— 直接取回等于原样重现 2026-07-28 这条。

### ⚠️ 删机型那条路径：**不要恢复**

它声称"刷总列表把被删机型从 nav/分区抹掉"。实测（同一机型跑两次 regen，
唯一差别 = catalog 里多/少一个**产品数为 0** 的机型）：

```
产出 24 vs 24 个文件 · 逐字节差异 0
```

**它写的是一批零变化的文件。** 而它以为自己在防的那件事也够不着：机型链接
**硬编码在官网的 `data/templates/_chrome.html` 页脚**（20 条），admin 不写那个文件，
删机型后全站页脚仍然链向它 —— 那份陈旧只有 `rebuild.mjs` 能修。

最后：它 rebake 的是 `categories[0]`，**和被删的那个机型无关**；而删机型的守卫要求
产品数 = 0。**⇒ 这条路径的代价（恒 62，取决于清单里第一个机型多大）与它要做的事完全无关。**
