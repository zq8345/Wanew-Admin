## 1. `card_title` —— 短名（治 h1 关键词堆砌）

| 项 | 值 |
|---|---|
| **位置** | `i18n[locale].card_title`（与 `title` 并列，**跟着语言走**） |
| **类型** | `string` |
| **可空** | **可空**。空/空白/缺失时 **admin 完全不写这个键**（不是写 `""`） |
| **也出现在** | `data/products-index.json` 条目：顶层 `card_title`，以及 `entry.i18n[loc].card_title` |

**为什么在 i18n 里而不是顶层**：产品标题本来就分语言（`i18n[locale].title`）。短名若是单语，pt/es 页会显示英文短名。

**回落规则（官网侧）**：`card_title` 缺失 → 用 `title`。
⇒ 今天所有产品都没有这个键，**渲染必须与加字段前逐字节一致**。

**长标题不动**：`title` 原样保留、继续经 `metaTitleOf()` 进 `<title>`。**SEO 一点不丢。**

**Admin 侧保证**：写入前 `trim()`；全空白视为空 → 不落盘。

## 2. `compatible_with` —— 适配终端（治"买家不知道配不配"）

| 项 | 值 |
|---|---|
| **位置** | 产品 JSON **顶层**（语言无关） |
| **类型** | `string[]` |
| **元素** | **机型 slug**（`"mini"` / `"standard-actuated"` / …），**不是显示名** |
| **可空** | **可空**。空数组/缺失时 **admin 完全不写这个键** |

**为什么存 slug 不存显示名**：显示名的真源是 `categories.json.display` + `locales.json.model_display`（admin 分类页在管）。存显示名 ⇒ Joe 改一次机型显示名就要回写 68 个产品 = 双源。存 slug ⇒ 显示名改了徽章自动跟着变。

**Admin 侧保证**：
- 选项源 = `data/categories.json` 的机型清单（与分类页同一份，没另造）。
- 校验：每个值必须是**现存机型 slug**，否则 400 拒；自动去重。
- **绝不从描述散文里推断**。存量 68 个产品**一律留空**，由人逐个补。

**官网侧期望行为**：
- 空/缺失 → **不渲染徽章**（现状不破）。
- 显示名解析优先级：**`model_display[slug]` > `categories.json` 里该 slug 的 `display`**；两者都查不到 → **跳过这一项**（不要回落成打印原始 slug，那对买家没意义）。

## 3. 官网两处判断 —— 我作为写入侧的确认

**① 询盘表单的 `subject` / `product` 隐藏字段保留长标题 → ✅ 确认，同意。**
理由成立且我补一条写入侧的依据：**短名没有唯一性约束**。admin 不校验短名重复（它是展示用的人话名，强制唯一会逼出 "Ethernet Adapter Cable 2" 这种更难读的名字）。所以短名**会撞**，长标题才是能定位到具体产品的那个。询盘要认出是 68 个里的哪一个，**必须用长标题**（更稳的是带上 `#id`）。

**② 徽章存 slug、显示名现查，优先级 `model_display > categories.display` → ✅ 确认，与我的意图一致。**
这正是第 2 节写的规则。补充一条边界：**两者都查不到时请跳过该项**，别打印 slug。
